\section{System Architecture \& Latency Defense}

\subsection*{Q1: How do you achieve an end-to-end voice latency of under 500\,ms?}
\textbf{Trap / What they are testing:} Verifying whether you measured each pipeline stage or picked 500\,ms arbitrarily.

\paragraph{Your Spoken Answer:}
We budget our 500\,ms turnaround across five pipelined streaming stages without waiting for full audio or text buffers:
\begin{enumerate}
    \item \textbf{Voice Activity Detection (Silero VAD):} Processes 20\,ms PCM frames and cuts off speech processing after 150\,ms of trailing silence.
    \item \textbf{Streaming STT (Whisper / Sarvam AI):} Streams audio over WebSockets and emits the final transcript within 120\,ms of speech end.
    \item \textbf{Parallel Intelligence Loop (\texttt{va\_icecot.py}):} Memory retrieval, emotion fusion, and intent classification run concurrently. Groq LLaMA 3.3 emits the first token in 120\,ms.
    \item \textbf{Streaming TTS (Cartesia):} Emits synthesized audio chunks over WebSocket within 80\,ms of receiving the first sentence token.
    \item \textbf{LiveKit WebRTC Transport:} Adds 15 to 25\,ms of jitter buffer delay.
\end{enumerate}
Summing these stages: $150\,\text{ms} + 120\,\text{ms} + 120\,\text{ms} + 80\,\text{ms} + 20\,\text{ms} = 490\,\text{ms}$. By streaming sentence chunks rather than waiting for complete paragraphs, the caller hears speech well before the LLM finishes generating its full reply.

\noindent\textbf{Key Numbers to Quote:} 150\,ms VAD cut-off, 120\,ms Groq TTFT, 80\,ms Cartesia first-chunk, total pipeline $\approx 490$\,ms.

\vspace{1em}

\subsection*{Q2: Why did you decouple real-time voice from post-call processing using Trigger.dev?}
\textbf{Trap / What they are testing:} Understanding asynchronous processing, resource isolation, and event loop blocking in Python.

\paragraph{Your Spoken Answer:}
In voice agents, database indexing and LLM summarization take 2 to 5 seconds. If we ran summarization, vector embedding generation, and graph updates inside the FastAPI call loop or standard \texttt{BackgroundTasks}:
\begin{itemize}
    \item Python's \texttt{asyncio} event loop becomes blocked by CPU-bound JSON serialization and embedding calls, causing audio packet jitter and stutter on active calls.
    \item If the server restarts or an LLM call fails, the entire call summary is lost.
\end{itemize}
By pushing post-call events to Trigger.dev, we get isolated serverless execution, automatic retries with exponential backoff, and zero CPU load on our live voice streaming workers.

\section{Four-Tier Hybrid Memory Architecture}

\subsection*{Q3: Why 4 tiers? Why couldn't you just use a single RAG vector database for everything?}
\textbf{Trap / What they are testing:} This is your primary defense question as the memory lead. Examiners expect clear justification for why each tier is necessary.

\paragraph{Your Spoken Answer:}
A single vector database fails in voice systems because conversational context has four fundamentally different access patterns:
\begin{itemize}
    \item \textbf{Short-Term State (Redis):} Slot values (booking time, phone number) change every turn. Querying a vector database for active state costs 50\,ms and lacks atomic updates. Redis handles this in 2\,ms.
    \item \textbf{Semantic Memory (pgvector):} Vector similarity finds unstructured semantic facts across past calls using cosine distance. But vectors cannot navigate multi-hop relationships.
    \item \textbf{Episodic Memory (PostgreSQL):} Humans recall past interactions chronologically—\textit{``what happened on Tuesday?''} Vector distance cannot guarantee temporal order; relational tables with indexed timestamps do.
    \item \textbf{Knowledge Graph (FalkorDB):} If a caller asks \textit{``Can you apply the discount promised to my branch manager?''}, vector search fails because the link between Customer $\rightarrow$ Branch $\rightarrow$ Manager $\rightarrow$ Discount is a graph relationship. FalkorDB resolves this in Cypher queries in under 15\,ms.
\end{itemize}
In \texttt{retriever.py}, we query all four tiers concurrently using \texttt{asyncio.gather}, keeping total memory retrieval time bounded by the slowest query ($\approx 45$\,ms).

\noindent\textbf{Key Numbers to Quote:} Redis $\approx 2$\,ms, FalkorDB Cypher $\approx 15$\,ms, pgvector $\approx 40$\,ms, total concurrent retrieval $< 45$\,ms.

\vspace{1em}

\subsection*{Q4: What happens if FalkorDB or pgvector goes down during a live call?}
\textbf{Trap / What they are testing:} System resilience, error boundaries, and graceful degradation.

\paragraph{Your Spoken Answer:}
Our memory retriever implements strict graceful degradation. In \texttt{retriever.py}, every tier query runs inside its own isolated \texttt{try/except} block with timeout constraints:
\begin{itemize}
    \item If FalkorDB fails, \texttt{\_fetch\_graph\_context} catches the error, logs a warning, and returns empty entity lists: \texttt{\{"recent\_entities": [], "frustration\_topics": []\}}.
    \item If pgvector times out ($>80$\,ms), the pipeline continues using Redis short-term state.
    \item The live call never drops. The agent continues the conversation naturally without historical recall for that turn.
\end{itemize}

\section{Dual-Signal Emotion Fusion \& VA-ICECoT}

\subsection*{Q5: Why is emotion fusion weighted 60\% audio and 40\% text? Why not 50/50?}
\textbf{Trap / What they are testing:} Whether the fusion weights are scientifically motivated or arbitrarily assigned.

\paragraph{Your Spoken Answer:}
In telephone conversations, callers often speak polite words while their vocal tone betrays clear frustration—saying \textit{``Sure, take your time''} with high pitch and clipped cadence. A 50/50 split would cause the polite text to cancel out the caller's actual agitation.
\begin{itemize}
    \item Acoustic prosody (pitch variance, jitter, speaking rate) from Hume AI is an involuntary physiological signal that callers cannot easily disguise. We give it 60\% weight.
    \item Safety check in \texttt{fusion.py}: if audio confidence falls below 0.6 (due to microphone noise or packet loss), the system falls back to text classification:
    \[
    \text{dominant} = \text{audio} \quad \text{if } \text{confidence}_{\text{audio}} > 0.6 \quad \text{else } \text{text}
    \]
\end{itemize}
This provides sensitivity to frustration while guarding against acoustic distortion.

\vspace{1em}

\subsection*{Q6: What is VA-ICECoT and how is it different from standard LangChain or ReAct agents?}
\textbf{Trap / What they are testing:} Architectural innovation versus off-the-shelf libraries.

\paragraph{Your Spoken Answer:}
Standard LangChain or ReAct agents use sequential \textit{Thought $\rightarrow$ Action $\rightarrow$ Observation} loops. In a voice agent, that is unusable:
\begin{enumerate}
    \item Each reasoning step requires a distinct LLM call, driving latency to 3 to 5 seconds.
    \item The LLM can hallucinate tool parameters or get trapped in cyclic reasoning while the caller waits in silence.
\end{enumerate}
\textbf{VA-ICECoT (Voice-Adapted Intent, Slot \& Emotion Chain-of-Thought)} executes in a single structured turn:
\begin{itemize}
    \item Simultaneously extracts intent and slot parameters using Pydantic schemas.
    \item Fuses the caller's emotional state.
    \item Evaluates deterministic decision rules (\texttt{combined\_rules.py}). If a rule matches (e.g., \textit{Intent: Billing Dispute} + \textit{Emotion: Frustrated}), it immediately executes an escalation action without unconstrained LLM hesitation.
\end{itemize}

\section{Streaming Voice Pipeline, Hinglish \& WebCall}

\subsection*{Q7: How did you implement browser testing without phone numbers or SIP trunks?}
\textbf{Trap / What they are testing:} Highlighting Adarsh's contribution and your development testing workflow.

\paragraph{Your Spoken Answer:}
Adarsh built the WebCall testing studio using the \textbf{LiveKit WebRTC Client SDK} inside our Next.js frontend:
\begin{itemize}
    \item The browser captures microphone audio via \texttt{getUserMedia}, encodes it into Opus packets, and negotiates a WebRTC session with our LiveKit media server.
    \item Our Pipecat Python worker joins the same LiveKit room as an automated participant, subscribing to the user's audio track and publishing synthesized TTS audio directly back.
    \item This allowed our team to test latency, emotion detection, and memory retrieval inside the browser without incurring telephony carrier costs or buying DID phone numbers.
\end{itemize}

\vspace{1em}

\subsection*{Q8: How does VoCall handle Hindi-English code-switching (Hinglish)?}
\textbf{Trap / What they are testing:} Real-world feasibility for Indian multilingual callers.

\paragraph{Your Spoken Answer:}
Standard English STT models fail when Indian callers mix languages (\textit{``Mera payment deduct ho gaya but order confirm nahi hua''}).
\begin{itemize}
    \item We route audio to \textbf{Sarvam AI's Saaras STT}, which is trained on Indian accent phonetics and Hindi-English code-switching.
    \item For speech synthesis, we route through Sarvam's Bulbul TTS or Cartesia's multilingual models, maintaining consistent accent and prosody without robotic pronunciation of Indian names and terms.
\end{itemize}

\section{Evaluation, Edge Cases \& Limitations}

\subsection*{Q9: On Slide 11, your metrics say `To Be Evaluated'. Did you actually test the system?}
\textbf{Trap / What they are testing:} Distinguishing honest scientific methodology from unfinished work.

\paragraph{Your Spoken Answer:}
Yes, our core architecture, four memory tiers, emotion fusion algorithm, and voice pipeline are fully implemented and functional in our codebase.
We explicitly marked them as \textit{`To Be Evaluated'} on Slide 11 because we distinguish between functional integration and formal statistical benchmarking:
\begin{itemize}
    \item In unit and integration runs, our internal pipeline turnaround consistently clocks between 450\,ms and 520\,ms on Groq and Cartesia.
    \item However, publishing an academic claim of $>95\%$ intent accuracy or $>90\%$ emotion correlation requires testing across hundreds of standardized multi-speaker datasets (such as IEMOCAP or MELD) with human annotators.
    \item This formal, statistically validated empirical benchmark is the exact focus of our final project evaluation phase.
\end{itemize}

\noindent\textbf{Key Numbers to Quote:} Internal integration latency: 450--520\,ms. Target benchmarks: IEMOCAP, MELD, LibriSpeech.

\vspace{1em}

\subsection*{Q10: What are the main limitations of your system today?}
\textbf{Trap / What they are testing:} Knowing your system's weaknesses. Never claim a system is flawless.

\paragraph{Your Spoken Answer:}
We have identified three concrete technical limitations that we are actively addressing:
\begin{enumerate}
    \item \textbf{Acoustic Noise Sensitivity:} Under heavy ambient noise (traffic, low-quality cellular connections), Hume AI's acoustic emotion confidence drops, forcing fallback to text-only sentiment.
    \item \textbf{Cross-Session Entity Reconciliation:} If a customer calls from a different phone number, our system cannot automatically link them to their existing FalkorDB graph entity without explicit caller identification.
    \item \textbf{Cold Start on Vector Indexes:} In empty databases, pgvector requires sufficient call volume before semantic similarity yields high-value conversational context.
\end{enumerate}
